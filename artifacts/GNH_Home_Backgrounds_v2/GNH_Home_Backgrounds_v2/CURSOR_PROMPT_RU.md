# Задание: подключить фоны нового главного экрана GameNight Host

В проект добавлена папка `GNH_Home_Backgrounds_v2` с готовыми изображениями и примерами. Реализуй изменения в коде до рабочего результата. Сейчас выполняем первый этап нового главного экрана — только фон главной и его связь с существующей темой.

## Цель

Добавить декоративный фон с кубиками, мягким свечением по краям и камнями в нижних углах. Центр должен оставаться спокойным и читабельным. Используй предоставленные изображения; не генерируй замену и не рисуй вместо них похожие CSS-заглушки.

Сохрани действующие четыре темы и их характер:

| Тема | Требуемый фон |
| --- | --- |
| Neon | Почти чёрный синий, фиолетово-розовое и голубое свечение |
| Light | Светлый лавандовый с нежным розовым и бледно-голубым |
| Sunset | **Светлый** кремово-персиковый, кораллово-розовые акценты |
| Calm | **Светлый** серо-белый, очень мягкий шалфейный оттенок |

Sunset не должен становиться тёмно-бордовым. Calm не должен становиться тёмно-зелёным. Скриншоты в `references/current-theme-*.png` показывают существующие темы. `references/target-home-layout.jpeg` — направление будущего экрана; полную перестройку его блоков выполняем следующим этапом.

## Сначала изучи проект

Прочитай применимые AGENTS.md, посмотри состояние git и сохрани посторонние изменения. Найди реальную главную, корневую оболочку, стили, действующий ThemeProvider / hook / атрибут темы и способ сохранения выбора. Проверь, отличаются ли Mini App и WEB-оболочка. Изучи текущие CSS-переменные тем: они точнее оценок цвета со скриншотов.

Не проси пользователя выбирать технические детали, которые можно установить по коду. Адаптируй комплект к найденной структуре и существующим соглашениям.

## Выполни

1. Скопируй только нужные WebP из `assets/` в подходящий каталог исходников, например `src/assets/home-backgrounds/`. Сохрани понятные имена. PNG из `originals/` оставь для разработки, в production их не подключай.
2. Добавь декоративный компонент и стили, взяв за основу `integration/HomeBackground.tsx` и `integration/HomeBackground.css`. Это пример адаптации, а не замена текущей Home. Поправь пути импортов под реальный проект. Используй обычные Vite-импорты изображений, чтобы работали хеширование файлов и любой base path, включая GitHub Pages. Если проект использует иной проверенный способ, сохрани его с корректным base URL.
3. Получай тему из существующего источника. Если в коде другие ключи, сделай явный адаптер. Смена темы должна сразу менять фон; сохранение выбора и восстановление после перезагрузки должны работать как прежде. Не создавай параллельный ThemeProvider, отдельный localStorage-ключ, второй переключатель или определение темы через MutationObserver.
4. Подключи фон к внешней области **главной**, чтобы он был виден вокруг карточек и по краям экрана. Не прячь его только внутри узкой колонки карточек. Сохрани нынешний max-width контента, отступы, safe-area и скролл. На других маршрутах новый декоративный слой не должен появляться.
5. Используй верхнюю и нижнюю части иллюстрации отдельно либо равноценную адаптацию: кубики сверху, камни у нижних углов всей главной, пропорции объектов сохранены. Не растягивай изображение по двум осям через `background-size: 100% 100%`. Избегай `cover` на очень длинной странице, если он обрезает весь крайний декор. Для большого каталога между верхом и низом должен быть спокойный базовый цвет без повторяющихся швов.
6. В качестве основы и fallback используй подходящий существующий цвет темы. Если нужна отдельная CSS-переменная для фоновой подложки, добавь её локально к главной. `palette.json` содержит резервные ориентиры. Маски должны плавно смешивать изображение с основой. Light, Sunset и Calm остаются светлыми.
7. Изолируй CSS. Декор находится под контентом, не перехватывает нажатия, не добавляет высоту, не вызывает горизонтальный скролл и скрыт от accessibility. У изображений пустой alt. Не ставь overflow:hidden на оболочку с модалками; ограничивай только декоративный слой. Проверь слои относительно фиксированной навигации, меню, подсказок и PremiumOverlay.
8. Сохрани нынешние баннеры, тексты, карточки, шрифты, иконки, размеры, переходы, клики и визуальные токены панели темы. Если старый однотонный слой скрывает новый фон, измени только необходимый локальный слой главной; цветные поверхности карточек и модалок должны сохраниться.

## Скорость загрузки

- Используй обычную и мобильную WebP-версии с picture/srcset или эквивалентным выбором. Мобильные файлы имеют ширину 768 px, обычные — 1182 px.
- Первичная загрузка получает только изображение выбранной темы и подходящего размера. Статические импорты URL сами по себе допустимы; фактические запросы остальных тем, PNG и скриншотов при открытии главной не нужны. Не добавляй preload для всех тем.
- Не ожидай image.onload, decode(), всех тарифов или данных профиля перед показом главной. Сначала доступен существующий контент на резервном цвете, затем появляется декор.
- Два декоративных слоя одной темы должны ссылаться на тот же URL. Они могут использовать общий браузерный ресурс.
- Не добавляй новые npm-зависимости, внешние CDN, удалённые картинки, сетевые запросы к API, тяжёлые blur/filter, canvas/WebGL или бесконечные анимации ради этого фона.
- При сетевой ошибке изображения интерфейс остаётся видимым и рабочим. При повторном входе используются штатные механизмы кеширования статических файлов.

## Границы этой задачи

Реализуй фон и связь с темами. API, платежи, авторизация, выдача Premium, база данных, маршруты игр, счётчик пользователей, CORS, VPN-прокси, конфигурация развёртывания и текущие исправления загрузки не относятся к этой задаче. Сохрани их поведение. Полный перенос новой шапки, карусели и рядов игр будет следующим этапом.

Выполни изменения локально. Merge, push и deploy в рамках этого задания не требуются.

## Проверки

Запусти имеющуюся проверку типов, lint и production-сборку, подходящие для изменённых файлов. Сохрани существующие тесты; новые тесты, повторяющие CSS, не нужны.

В браузере проверь все четыре темы на ширине 360–390 px и 1440 px, длинный каталог и восстановление темы после перезагрузки. Для браузера без Telegram используй штатный dev-режим проекта; production-авторизацию не ослабляй. Проверь клики, скролл, меню и PremiumOverlay. В Network проверь, что при первом входе запрашивается только текущий WebP-ресурс подходящего размера, исходные PNG и остальные темы не загружаются, а отрисовка не ждёт фон. Ошибка загрузки изображения должна оставлять нормальную цветную основу.

Если для части проверок здесь нет среды, укажи конкретно непроверенное; не выдавай пример из комплекта за проверенную интеграцию в приложение.

## В конце сообщи

Кратко опиши изменённые файлы, откуда берётся тема, как решена адаптация края на телефоне и широком экране, фактический вес загружаемого фона и результаты проверок. По возможности приложи локальные скриншоты четырёх тем. Пользователю нужен готовый рабочий результат в проекте, а не только план.
