# Правильная вставка портала и НОВЫХ широких обложек

Исправь отображение изображений главного экрана GameNight Host, используя этот пакет. Здесь расширены НОВЫЕ сцены из последнего набора, а не старые космические иллюстрации: Cards — гостиная с карточками; «Кто тут кто?» — друзья у загородного дома; «Где мы?» — поезд, озеро и российский пейзаж.

## Файлы и область задачи

- Сначала прочитай ASSET_MAP.json: в нём точные файлы, исходные размеры и пропорции для desktop/mobile.
- assets/*-desktop.webp — широкие версии для показанных длинных карточек и портала.
- assets/*-mobile.webp — отдельные варианты для телефона. Три обложки 3:2 — из последнего одобренного набора, портал имеет собственную вертикальную композицию.
- originals/ — PNG в исходном разрешении, не включай их в стартовую загрузку сайта.
- Подключи только портал и обложки трёх существующих игр. Не переименовывай реальные game ID; сопоставь по существующему каталогу. «Где мы?» также может иметь текущий ключ russia-travel.
- Остальные 12 новых обложек остаются из предыдущего набора. Не возвращай старые космические обложки и портретную картинку с открытками.

## Почему появлялись растяжение, зум и пустые поля

Входные картинки имели другие пропорции, чем длинные контейнеры. Новые desktop-файлы уже нарисованы под широкий формат. Вместе с ними исправь геометрию контейнера: нельзя вставить новый файл и сохранить конфликтующий фиксированный height или aspect-ratio старой карточки.

## Портал — обязательно полностью

1. Вынеси ТОЛЬКО визуальную область hero за пределы центрального max-width контейнера, чтобы её ширина равнялась ширине доступной страницы. Контент текста оставь в действующей сетке.
2. Покажи всю картинку через img/picture. Высота области должна определяться реальными пропорциями файла из ASSET_MAP.json, а не произвольной фиксированной высотой. Общая схема приведена в styles/responsive-assets.css и components/ResponsiveArtwork.example.tsx.
3. Не используй background-size:cover, object-fit:fill, scale, растягивание по двум независимым осям или crop для портала. object-fit:contain в контейнере ТОЧНО ТЕХ ЖЕ пропорций не создаёт пустых полос.
4. Арка, цветы над аркой и все ступени должны помещаться целиком. Не придвигай портал к камере ради заполнения экрана. Не обрезай его сверху шапкой: hero начинается ПОСЛЕ шапки; отрицательный margin-top не нужен.
5. На экране <=640px переключи picture на portal-mobile.webp и меняй пропорции обёртки на пропорции mobile-файла. Не вырезай мобильную картинку из desktop панорамы.
6. Заголовок, подзаголовок и CTA остаются настоящими текущими HTML-элементами. На desktop текст располагается слева; на mobile — в свободной верхней зоне. Если длинный текст не помещается, вынеси его над изображением на mobile, сохранив всё изображение.
7. Выбор режимов размещай ниже hero или вне области, содержащей арку и ступени. Не закрывай ими портал. Непрерывный существующий фон страницы сохрани.

## Три длинные карточки

1. На desktop используй desktop.webp каждой игры. На mobile <=640px — соответствующий mobile.webp через picture/source.
2. Пропорции родителя picture меняются вместе с выбранным файлом. Точные значения бери из ASSET_MAP.json, не угадывай по скриншоту. Изображение: display:block; width:100%; height:100%; object-fit:contain; object-position:center.
3. Не задавай одновременно случайные фиксированные width и height. Не используй портретную картинку внутри длинного баннера, не размывай копию картинки по краям, не меняй геометрию людей.
4. Удали конфликтующие старые правила cover/zoom/scale только у этих трёх обложек и портала. Не сломай остальные режимы и иллюстрации. Не добавляй глобальные правила img.
5. Заголовки игр, метаданные и Premium/NEW/ХИТ остаются HTML из реального каталога. На широком баннере подпись можно оставить слева внизу, в подготовленной свободной области; на mobile при необходимости вынеси подпись под изображение, чтобы не закрывать лица. Названия должны читаться: ориентир 28–36px desktop, 24–28px mobile, без принудительного обрезания.
6. Кнопки, переходы, избранное и доступ Premium сохраняют действующие обработчики. Не добавляй заставки при входе, не меняй рулетку, её вероятности и список игр.

## Сохранить приложение

Все игры, вопросы, колоды, описания, реальные цены и тарифы, профиль, авторизацию, оплату, Premium-права, согласия, ссылки на документы, Telegram SDK, Capacitor, offline, маршруты, состояния и исправления скорости оставить действующими. Не переносить демо-данные и JS из визуальных прототипов.

Пути к публичным ассетам адаптируй под реальный Vite base / GitHub Pages / web / Capacitor; не предполагай абсолютный корень домена. Для картинок ниже первого экрана — lazy и decoding async. Не грузить все PNG и обе версии picture одновременно.

## Проверка

Один раз проверь ширины 390, 768, 1440 и 1920: целая арка и ступени, корректное переключение файлов, отсутствие растянутых лиц и пустых боковых полос, нет горизонтального скролла, заголовки читаемы и не закрывают лица. Если пропорции контейнера не совпадают с ASSET_MAP, исправь контейнер, а не искажай файл. Выполни существующую сборку/typecheck при наличии.

В конце перечисли изменённые файлы и подключённые соответствия. Не делать merge, production-деплой, миграции БД, оплату и переделку остальных экранов.
